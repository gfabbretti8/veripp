The function ignores utf8_len entirely ("TODO: Check for runover") and writes up to 3 bytes per UTF-16 code unit. The counterexample has 3 code units, two of them >= 0x800, needing 7 output bytes for a 4-byte destination. The single call site converts in place: it reads from buf + 1 and writes to (uint8_t *)buf, so the destination holds about 2 bytes per code unit while the output can need 3. Code unit values come from a device string descriptor, so values >= 0x800 are feasible, and nothing at the call site bounds the output. The harness's shape (a destination of utf8_len bytes that the function is told about and ignores) is a fair model, and the overrun is reachable by a real caller.
