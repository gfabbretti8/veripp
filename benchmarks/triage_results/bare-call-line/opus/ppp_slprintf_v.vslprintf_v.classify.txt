The only caller passes `ruser` together with an explicit length `ruserlen` as the precision. Pairing a buffer with a length like this is the usual sign of a length-delimited field (for example a peer name copied out of a received packet), which is not guaranteed to be NUL-terminated. The caller depends on `prec` to bound the read. But the function calls `strlen(p)` before it applies `prec`, because `fillch` is always ' ', so the precision never limits the scan. When `ruser` holds exactly `ruserlen` bytes and no terminator, `strlen` reads past the buffer. The harness's unterminated 4-byte string with prec = 3 is the case the caller's use of a precision is supposed to make safe. The precision is not respected, so a real caller can trigger the over-read. This is the known unbounded strlen in the "%.*v" handling.
