The only call site passes `ruser`, an 8-byte buffer with no terminator, and the comment in the caller says this is deliberate: a PAP username field that runs to the end of the datagram. The caller also passes `ruserlen` as the precision, but the function only uses that precision when `fillch == '0'`, and here `fillch` is `' '`. So the `strlen((const char *)p)` on the unbounded path runs on the caller's unterminated buffer and reads past its end. This is a feasible input that a real caller produces, so it is a real defect, not a harness artifact.
